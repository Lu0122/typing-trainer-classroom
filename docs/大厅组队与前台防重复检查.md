# 游戏大厅组队与前台防重复检查

## 使用

学生登录后进入游戏大厅，点击右下角“组队聊天”。可发送文字，或发起赛车、生死时速、音游、淘汰赛、阵营对抗邀请；发起后进入对应房间，对方点击邀请卡片加入。收起聊天时，新消息会显示短提示。对局已开始、房间已满或已关闭时，以服务端校验结果为准。正式比赛检录、进行或暂停时，比赛锁继续阻止进入其他游戏。

聊天与实时房间目前都保存在教师机服务进程内：重启服务会清除聊天、邀请和未结束的实时房间；旧邀请带有服务实例标识，不能误加入新服务创建的房间。聊天内容不是长期存档。教师机客户端需要同一套新前后端，旧服务应在课堂结束后重启；Windows 运行包需重新构建才能包含此功能。

## 防重复与并发

- 聊天和发起邀请：前端请求期间锁定按钮；服务端按账号和请求标识去重，并限制发送频率。断网未确认时保留请求标识用于重试。
- 加入邀请：前端统一锁定邀请和加入操作；服务端复用游戏的房间验证，并确保重复进入不会增加座位。服务端在加入前校验房间状态、容量和实例标识。
- 学生端账号登录、注册、头像、挑战开始与交卷、反馈提交、游戏加入/开始/输入/退出等主要异步入口已检查；为缺失的同步忙碌锁补保护。遗迹逃亡在等待状态请求后再次检查写入锁，避免重复发包；排行榜使用请求序号防旧结果覆盖；大屏避免堆叠轮询。
- 不对键盘输入统一套用定时防抖：赛车、音游和比赛的输入具有独立的批处理、顺序与计分逻辑，强行延迟会影响玩法。

## 测试边界

自动化覆盖 60 个模拟身份争抢同一四人房、重复请求、房间关闭、服务重启、比赛锁、输入发送等待及主要回归。隔离数据库和浏览器模拟验证五种邀请、折叠消息提示、窄屏和重复点击；这些不是 60 台真实设备的课堂网络测试，也不证明长时间运行或高并发聊天下的生产容量。
