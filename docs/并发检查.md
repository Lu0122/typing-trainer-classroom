# 60 人并发检查

当前学生端主要使用 HTTP 轮询与输入批量提交。Node.js 后端使用 SQLite WAL；实时房间部分状态保存在进程内存中。服务重启会影响正在进行的实时对局。

在开发环境项目根目录运行 `node scripts/concurrency-check.cjs`。脚本启动独立的本机服务，使用系统临时目录中的独立 SQLite 数据库和 60 个模拟身份，不访问或修改课堂数据库。运行后会输出临时数据库目录，便于检查；文件不会自动删除。

脚本先让 60 人加入红蓝占领战，然后在约 10 秒内模拟状态和赛事列表轮询、300 次分批输入及 240 次普通练习记录写入。它输出各接口响应时间（毫秒）的 p50、p95、最大值，错误数、练习记录数与事件循环延迟；请求失败、题目获取失败或练习记录数量不符时退出码为非零。

2026-11-04 本机一次运行：1,800 次计量请求（含 60 次加入），无 HTTP 错误；240 条指定的普通练习记录写入。状态与赛事查询 p95 分别为 403 / 404 毫秒，输入提交 p95 为 470 毫秒，练习记录写入 p95 为 471 毫秒。客户端和服务端在同一台电脑上运行，结果会受机器负载影响。

这是短时间的本机回环合成测试，不包含实际教室网络、60 台浏览器渲染、持续高速打字、真实数据库规模、同时登录或全部玩法。正式使用前应在教师机和教室网络下，用接近实际人数、模式和时长进行试运行，并关注响应、断线、成绩和机器资源。普通练习记录离线后目前没有持久化补发队列，断网时可能丢失；教师机重启、地址改变和 Wi-Fi 信号问题也不由此测试覆盖。
