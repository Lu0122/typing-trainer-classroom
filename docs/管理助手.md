# 管理助手（AI 后台助手）

后台右下角的「管理助手」浮标：老师用自然语言提问，助手自己决定调哪个工具、必要时自己写 SQL 查库，或者给出 CSV 下载链接。

## 能做什么

| 能力 | 说明 |
| --- | --- |
| 自由查询 | 助手自己写单条 `SELECT`，服务端硬性校验后才执行 |
| 内置工具 | `overview`（概览）/ `students`（学生列表）/ `student_detail`（学生档案）/ `progress`（学习进步）/ `class_overview`（班级对比）/ `inactive_students`（未练习名单）/ `trend_compare`（趋势环比）/ `key_diagnosis`（错键诊断）/ `mode_accuracy`（模式准确率）/ `assignments`（教学任务）/ `feedback`（意见反馈）/ `competition_results`（比赛结果）/ `classes`（班级列表） |
| 导出 | `export_progress`（学习进步）、`export_scores`（竞速成绩）、`export_competition_event`（比赛赛事成绩）、`export_competition_result`（打字比赛成绩）、`export_sql`（把当前查询结果导成 CSV） |
| 连续对话 | 每次提问写入 `agent_audit_logs`，下一轮从中取最近 8 轮做上下文 |

导出的四个工具**直接复用页面上的下载接口**，不另写一份 CSV：

- `export_progress` → `GET /api/admin/agent/exports/progress.csv`
- `export_scores` → `GET /api/admin/scores/export?format=csv`
- `export_competition_event` → `GET /api/competitions/:id/export.csv`
- `export_competition_result` → `GET /api/competition/:mode/export.csv`

竞速成绩的筛选条件抽在 `backend/score-filters.js`，页面和助手共用一份，避免同一个问题在两处得到不同数字。

## 界面

后台左侧导航「管理助手」是独立页面，不是弹窗：

- 左边是**历史对话**列表（标题取第一句话前 18 字，显示条数和更新时间，可删除）。
- 右边是对话区，空间够宽，明细表格不会被挤扁。
- 选中的会话记在 localStorage，**刷新后自动回到同一个对话**；没记录时打开最近一个，再没有就开新的。
- 会话和消息都存在 `agent_conversations` + `agent_audit_logs.conversation_id`，重启服务也不丢。

## 行数与进度

- 工具结果上限 `MAX_ROWS = 100`，交给模型的行数上限 `RESULT_PREVIEW_ROWS = 100`。
  原来 20 / 8 / 回答阶段再截到 5，导致「65 人没练习」被说成「前 5 位是…」。
- 名单类工具（未练习、学生列表）会额外返回 `rowCount`（真实总数），
  `total` 和 `rows.length` 不一样时，说明数据被截断。
- 提示词要求：**名单一次性列完**，不要写「前 N 个」「其余还有 N 人」。

流式回答推三种事件：`meta`（会话 id）/ `progress`（正在理解 / 查到 N 条）/ `delta`（增量文本）/ `done`。
前端在气泡里显示「正在理解你的问题」+ 三个跳动的点，20 秒后换成「还在处理，请稍等」。

## 流式回答

`POST /api/admin/agent/chat?stream=1` 走 SSE，回答边生成边推给浏览器：

```
event: meta   data: {"conversationId":4}
event: delta  data: {"text":"本周有训练"}
event: delta  data: {"text":"数据，上期没有"}
event: done   data: {"reply":"完整回答","conversationId":4,"streamed":true,"downloads":[]}
```

- 用 Qwen 的 OpenAI 兼容流式（`stream: true`），见 `backend/customer-service.js` 的 `streamModel()`。
- 流式下**不用 response_format**：JSON 边生成边截断没法解析，所以回答直接输出正文。
- 前端用 `fetch` + `ReadableStream` 解析 SSE，逐字追加到气泡。
- 超时 120 秒；流式一个字都没出时退回非流式再要一次，仍失败才用 `factualReply()` 的事实话术。
- **`enable_thinking` 必须放在请求体顶层**：DashScope 的 OpenAI 兼容接口不认 `extra_body`，
  放进去会被忽略，模型按默认开启「思考」，首字要十几秒（实测 65 行数据首字 50 秒，改完 0.75 秒）。

## 结果怎么回到界面

工具结果统一转成「列 + 行」再交给模型和前端（`buildResultView`）：

```
{ tool, label, total, columns: ['displayName','className'], labels: ['姓名','班级'], rows: [['李雷','25软件1班'], ...] }
```

- 给模型的提示词要求**用自然语言叙述**：先给结论，再补细节；超过 8 条说「共 N 条，前 8 位是…」；
  不许贴 JSON、不许出现字段名、不许贴下载链接原文。
- `labels` 是中文表头（`COLUMN_LABELS`），界面直接用它，不再显示 displayName 这种字段名。
- 界面**不再显示数据表**：老师要的是结论，明细只存在审计日志里供事后核对。
- 每份结果最多带 8 行（`RESULT_PREVIEW_ROWS`），`total` 是真实条数，超出会标注「只显示前 8 行」。

## 多步思考

第一轮工具执行完后，如果问题里有多个目标（含「和 / 以及 / 对比 / 分别 / 同时 / 还有 / 另外」）
或第一轮全部失败，会把已有结果回喂给模型再要一轮 toolCalls（最多再 2 个）。
数据已经够用时模型会返回空 toolCalls，不会无限循环。

## 防编造

- 问题看起来在问数据（含「查/多少/几/谁/哪个/哪些/趋势/对比/统计/排行/结果/详情/导出/成绩/训练/练习/学生/班级/模式/错键」）
  但模型一个工具都没调时，服务端会用内置规则**强制查一次**，避免它凭空给数字
  （实测曾出现「哪个模式准确率最低」不调工具就答「89.2%」）。
- 时间戳统一转成 `YYYY-MM-DD HH:mm` 再交给模型，避免回答里出现 `1792986387105`。

## 安全边界（只读，代码层拦截，不靠提示词）

助手**不能改数据**。任何 `INSERT / UPDATE / DELETE / DROP / ALTER / CREATE / PRAGMA / VACUUM / ATTACH` 都会被拒绝，模型被诱导也没用。

`inspectReadOnlySql()` 依次检查：

1. 不能为空、不超过 8000 字符、不含 `\u0000`
2. 不允许 `--` 和 `/* */` 注释
3. 不允许 `;`（单语句）
4. 先把字符串字面量挖空再判断，避免 `WHERE name = 'delete'` 被误杀
5. 必须以 `SELECT` 开头（`WITH ... SELECT` 也拒，图省事）
6. 禁用词表：`insert/update/delete/replace/upsert/merge/alter/drop/create/truncate/vacuum/reindex/attach/detach/pragma/begin/commit/rollback/savepoint/release/grant/revoke/explain/load_extension/readfile/writefile`
7. 禁用标识符：`admin_accounts`、`ai_settings`、`agent_audit_logs`、`password_hash`、`api_key_ciphertext`、`token_hash`、`attachment_data`、`avatar_data`、`scenario_json`、`history_json`、`sqlite_master` 等
8. 不允许 `SELECT *`（必须显式列字段）
9. `LIMIT` 只能是 ≤ 500 的整数

执行阶段再加两道：

- 用**独立的只读连接**（`new Database(path, { readonly: true })`）跑查询
- 没有 `LIMIT` 的语句会被套成 `SELECT * FROM (原句) AS ai_query LIMIT 500`，返回前再按 500 行 / 120KB 截断

## 失败回喂

工具执行失败（SQL 为空、导出条件不满足、工具不存在）时，会把错误原因回喂给模型重来一次；仍失败才如实告诉老师，不会包装成「没有查到数据」。

## 审计

每次提问写一行 `agent_audit_logs`（管理员、提问、调用工具、结果摘要、来源、时间）。
后台「助手审计」页可查，支持关键词搜索、时间筛选（今天 / 最近 7 天 / 最近 30 天）、分页和每页条数。
接口只回摘要（工具名 + 回复前 300 字），不下发整份结果 JSON。

## 使用提示

- 输入框里回车是换行，**Ctrl + 回车** 才发送（⌘ + 回车 也行）。
- 没有配置 AI Key 时走内置规则（`fallbackPlan`），常见问法仍然可用，但回答是模板化的。
