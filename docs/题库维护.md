# 三个练习入口的题库维护

首页的“新手入门”“英文打字”“拼音打字”使用前端本地题库，不读取 `data/` 里的 SQLite 数据库。修改题库后执行 `npm run build`，刷新页面即可看到新内容。

## 新手入门

在 `frontend/src/lesson-bank.js` 的 `beginnerLessons` 数组里增加一关。每关填写 `title`、`hint` 和 `items`，目标键可用 `buildKeys(['KeyA', 'KeyS', 'KeyD', 'KeyF'], 120)` 生成。页面顶部的“选择键位课程”可直接跳转；同一关每次开始时都会重新排列目标键。

## 英文打字和拼音打字

普通素材放在 `frontend/src/lesson-bank.js` 的 `extraEnglishCopy`、`extraPinyinCopy`；批量扩充放在 `frontend/src/lesson-expansion.js`：

- `themes` 每项是“主题名、英文单词字符串、中文词组字符串”。新增一项会同时增加一套英文单词和一套拼音词组。
- `articles` 每项是“中文标题、英文标题、中文文章、英文文章”。新增一项会同时增加英文语句、英文文章和拼音文章。文章在页面中自动分行，不需要手工截断。
- 音节练习在 `extraPinyinCopy['pinyin-syllable']` 中用 `syllableSet('名称', [['ba','八'], ['ma','马']])` 增加；拼音输入目标会由音节自动拼接，汉字用于提示。

每套素材的 `selector` 应唯一，便于下拉框选择。已有课程完成后会顺序切换到下一套，最后一套完成后循环；浏览器会记住每类课程上次使用的编号。这个记录只影响练习位置，账号成绩仍由服务端保存。

## 打包

在项目根目录运行 `powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\package-source.ps1`。压缩包保存在 `output/packages/`，包含当前 `.env` 和题库源码，排除 `data/`、`node_modules/`、日志、截图等本机数据。

## 后台「练习文章」的分类用途

后台“内容管理 → 练习文章”里的文章存在 `passages` 表，和上面的本地题库是两套东西。分类决定这篇文
章会被谁取走，改分类前先看这张表：

| 分类 | 前台谁在用 | 语言 |
| --- | --- | --- |
| 一分钟挑战 | 竞速模式（默认/旧版入口） | 中文 |
| 英文挑战 | 竞速模式（英文） | 英文 |
| 拼音挑战 | 竞速模式（拼音输入法） | 中文（学生用拼音输入法打） |
| 校园生活 / 成长励志 / 生活随笔 / 科技阅读 | 比赛「指定文章」、占领战阵营赛 | 中文 |
| 英文打字 / 拼音打字 | **前台没有任何入口会用到** | — |

后两行是历史遗留：首页的“英文打字”“拼音打字”卡片走的是本地题库（见本文开头），比赛候选池又会过
滤掉拼音文章。所以后台新建文章时这两个分类已从下拉里移除；库里已有的旧文章仍能编辑和回显，不会丢。

列表页的“分类”筛选**保留**这两个分类，单独归到“前台未使用（历史文章）”分组，方便把旧文章筛出来
编辑或删除。两个下拉共用同一套分组（`public/admin.js` 的 `groupPassageCategories()`），不要再手写
一份选项，否则又会两边对不上。

## AI 生成文章的语言规则

`AI 生成文章` 按**分类**决定语言，不由模型自由发挥，规则在 `backend/article-prompt.js`：

- 中文分类 → 中文正文。生成后会自动删掉正文里的空格（前台逐字比对，多一个空格就会被算成打错），
  换行保留用来分段。
- `英文挑战` → 英文正文。出现汉字或全角标点会被判为不合格。
- 生成结果不合格时，会把原因回喂给模型重生一次；仍不合格就报错、不写库，避免脏数据进题库。
- 下拉里选不到的分类（`英文打字` / `拼音打字`）不能生成，按钮置灰并说明原因。
- 模型返回的分类一律忽略，保存的就是老师选的那个，避免「选了英文分类、库里存成别的」。

改这套规则后跑 `node --test test/passage-ai-language.test.js`。
