# 字练场课堂稳定性与后台改造计划

## 目标与范围

支持教师机运行服务、最多 60 名学生通过浏览器使用的课堂场景。围绕成绩可靠保存、多人游戏实时同步、教师后台易用性和 Windows 离线运行包开展改造。后台页面重构与游戏通信改造分阶段验证，不以更换组件库代替并发治理。

## 当前基础

- 学生前台：Vue 3 + Vite；教师后台：`public/admin.html`、`public/admin.js`、`public/admin.css`，当前并非 Vue 页面。
- 后端：Node.js + Express，SQLite；游戏主要通过 HTTP 轮询和批量提交输入。部分实时房间状态在进程内存中。
- 运行方式：教师机提供服务，学生浏览器通过局域网访问；Windows 运行包支持离线启动与更新。
- 已有基础：账号、班级、文章、教学任务、成绩、比赛、反馈、管理助手、后台账号等。改造前逐项盘点实际功能，形成新旧功能对照表。

## 推荐技术方向

- 教师后台改为 Vue 3 + Vite + Element Plus，使用中文组件、统一表格/表单/提示，并沿用现有后端 API 和权限规则。Element UI 对应 Vue 2，现有项目应选择 Element Plus。
- 管理后台构建产物随运行包本地提供，教室使用不依赖外部 CDN；开发时锁定依赖版本。
- 游戏通信采用 HTTP + WebSocket：仅多人实时玩法分批试点；账号、普通管理和低频查询继续使用 HTTP。大屏根据需求选择推送方式。
- 重要结果以服务端确认和持久化为准；WebSocket 负责实时交互，不能代替断线恢复和可靠存储。

## 阶段 1：基线与数据可靠性

1. 盘点所有后台页面、操作、角色权限、API、导入导出与现有课堂流程，记录当前体验及问题。
2. 为普通练习记录实现本地待提交队列，区分账号，服务端复用唯一标识去重；保存失败、身份过期、浏览器存储不可用等情况提供提示。
3. 测试断网、恢复、刷新、重复提交及同浏览器切换账号；记录真实教师机和课堂网络基线。

验收：记录只写入正确账号一次；待提交和失败状态可识别，不可恢复的情况明确提示。

## 阶段 2：后台基础框架与试点

1. 新建独立的 Vue 后台入口，规划 `/admin` 和现有 hash 链接的兼容；迁移期间保留旧后台的可回退入口。
2. 建立登录、角色权限、页面布局、导航、API 调用、加载/空状态/错误提示和连接状态；后台操作始终由服务端校验权限。
3. 以学生账号或反馈管理为试点，迁移搜索、筛选、服务端分页、详情和常用操作；兼顾 60 人课堂与大数据量场景。
4. 统一 Element Plus 中文文案、交互、响应式布局和适当的项目视觉样式。

验收：试点页面的功能、权限、查询结果和关键操作与旧版一致，基础浏览器交互及网络异常提示通过；新旧入口均可按设计访问。

## 阶段 3：后台业务逐步迁移

按模块迁移并逐项与原版对照：

1. 学生账号和批量导入、班级和成员管理。
2. 练习文章、教学任务、成长与训练进度、排行榜和成绩导出。
3. 比赛管理、现场控制、投影与结果导出；保留已有强制参赛和终止规则。
4. 学生反馈与附件、管理助手及其流式响应、AI 设置、管理员账号与角色权限。
5. 教师机运行状态、课堂访问地址、服务/连接异常与操作反馈。在线人数等信息只有在服务端能可靠提供时才显示，并说明统计范围。

每个模块迁移前先核对当前实现，保持已有功能和权限；分页、筛选、导入导出、大批量操作和错误处理不能因 UI 重构退化。确认旧功能覆盖并经过课堂流程验证后，再切换默认入口。

## 阶段 4：实时通信与单模式试点

1. 建立 WebSocket 服务，复用现有学生身份认证，校验来源、会话、消息大小及频率。
2. 建立心跳、断线退避重连、消息确认与去重；恢复时重新获取服务端状态。定义服务重启和会话过期时的行为。
3. 先选择红蓝占领战试点：状态推送、输入批量提交、确认和恢复；保留 HTTP 初始状态读取及明确的异常恢复方案。
4. 比对原规则、队伍、计分和落库结果；不将 60 人本机短时模拟视为真实课堂验证。

验收：重复消息不重复计分，断线和重连后状态可恢复或明确告知无法恢复；建立对照基线并评估响应、请求量、资源与稳定性。

## 阶段 5：60 人验证与逐步推广

- 检查 60 人同时进入、登录、持续输入和结算，后台同时操作及导出；覆盖多客户端断网、重连、刷新、教师机重启及地址变化。
- 在实际教师机和教室网络中，按真实使用人数、浏览器、数据规模和课堂时长试运行，记录错误率、响应时间、重连、成绩一致性及 CPU/内存。
- 根据基线确定验收阈值；试点通过后再按比赛、赛车、生死时速、音游及淘汰赛的使用需求分批迁移。单人模式根据实测决定是否迁移。

## 发布、兼容与回退

- 保留数据库和 `.env`，发布前备份；数据库结构变更遵循现有迁移与备份机制，检查新旧版本兼容。
- 更新构建、Windows 打包、增量更新清单和运行包验证，确保新后台静态资源及依赖完整进入离线包；检验旧地址、更新和回滚。
- 每阶段分别进行代码测试、浏览器操作验证和必要的并发测试；正式切换前保留旧后台/旧版本的明确回退方案。
- 最终交付注明已验证范围、课堂实测结果、仍有限制和使用说明；不把模拟结果当作真实课堂验收。

## 实施进展（2026-11-04）

- 普通练习记录：已加入按学生账号隔离的本地待提交队列和服务端账号核对；断线、响应丢失后可按唯一标识重试。本地存储不可用时仅能暂存在页面内存；教师机地址变化后，新地址无法读取旧地址的浏览器队列。
- 后台：新增 Vue 3 + Element Plus 反馈管理试点 `/admin-next.html`，原 `/admin` 继续使用。隔离数据库中已验证登录、列表、详情和修改状态；其他后台模块尚未迁移。
- 实时游戏：普通红蓝占领战增加已登录用户的只读 WebSocket 状态流，输入仍通过 HTTP 提交；断线回退 HTTP。当前每秒发送完整快照，未证明降低状态计算或网络负载；团队比赛与其他模式尚未迁移。
- 验证：本机自动化测试 300 项通过；已验证独立构建产物包含新后台资源。完整 Windows ZIP、更新和回滚、真实教室网络、浏览器长连接断线恢复及长期 60 人负载仍待验证。

## 后台迁移进展（2026-11-04，续）

`/admin` 现转到 Vue 3 + Element Plus 后台并保留原有页面片段链接；原后台保留在 `/admin-legacy.html`。新版已接入概览、学生、班级、文章、任务、学习进步、竞速成绩、比赛、反馈、后台账号、AI 设置、管理助手与审计。普通红蓝对抗以外的游戏通信改造仍未完成。

隔离数据库验证覆盖学生与班级、部分导入失败、文章与任务、周报/成绩导出、比赛创建与检录、后台账号及权限、助手内置模式和反馈等代表性操作。真实 AI、全部筛选组合、Excel 导入边界、完整 Windows ZIP 与真实教室网络仍需验证。后台代码变更需要重启教师机服务后完整生效；旧服务未返回学生 classId 时新版会阻止学生编辑以保护班级归属。
