# 项目结构说明（前后端怎么分）

> 一句话：**前端只有 `frontend/`，后端只有 `backend/`，其余目录都不是源码。**
> 如果你在资源管理器里还看到一个 `src/` 文件夹，那是改名前的旧视图，按 F5 刷新就没了（`src/` 已经整体改名为 `backend/`）。

## 一、根目录五类文件夹，性质完全不同

| 目录 | 属于哪一端 | 能不能手改 | 说明 |
| --- | --- | --- | --- |
| `frontend/` | **前端** | ✅ 能 | Vue 3 源码，跑在浏览器里。改这里 = 改界面、改交互 |
| `backend/` | **后端** | ✅ 能 | Node + Express 源码，跑在服务器里。改这里 = 改接口、改规则、改房间逻辑 |
| `public/` | 前端**产物** | ❌ 别改 | `npm run build` 自动生成，改完会被下次构建覆盖 |
| `data/` | 运行时数据 | ⚠️ 别手改 | SQLite 数据库（`typing.db`）、日志。删了就丢成绩 |
| `output/` | 运行产物 | ❌ 别改 | 验收脚本截图、诊断输出，已加入 `.gitignore` |
| `scripts/` | 工具 | ✅ 能 | 验收/截图/测量脚本，只在手动跑时用到，不影响服务 |
| `test/` | 测试 | ✅ 能 | `npm test` 跑，测的是 `backend/` |
| `docs/` | 文档 | ✅ 能 | 规则、QA 记录、变更日志 |

**记法：源码只有两个目录，一个浏览器端（frontend），一个服务器端（backend）。`public/` 长得像源码，其实是构建出来的，改它等于白改。**

### 根目录还散着 8 个文件，它们属于「整个项目」，不属于任何一端

| 文件 | 干什么用的 | 能挪走吗 |
| --- | --- | --- |
| `package.json` | npm 的身份证：依赖清单 + `npm start / test` 脚本 | ❌ 不能。npm 从当前目录往上找它，挪走等于换了个项目 |
| `package-lock.json` | 锁死每个依赖的具体版本，保证换机器装出一样的东西 | ❌ 不能，必须和 `package.json` 同目录 |
| `vite.config.js` | 前端构建配置（`root: frontend`、产物输出到 `public/`） | ⚠️ 唯一「本质属于前端」的根文件，可以搬进 `frontend/`，但要同步改 `package.json` 里的 `--config` 路径 |
| `.env` | 真实运行参数：端口、后台密码、数据库路径 | ❌ 不能。`backend/server.js` 里写死了读上一级的 `.env` |
| `.env.example` | 参数模板，提交到仓库给人参考 | ❌ 同上，和 `.env` 放一起 |
| `.gitignore` | 告诉 git 哪些文件不提交 | ❌ 不能。git 只认仓库根（和各级子目录）的 |
| `README.md` | 项目门面，启动步骤说明 | ❌ 不能。GitHub / Gitee 只渲染根目录这一份 |
| `start-server.bat` | 双击启动（先构建前端，再起后端） | ❌ 不能。里面 `cd /d "%~dp0"` 就是「切到本文件所在目录」，靠这个相对路径找 `node_modules` 和 `backend` |

**判断规则：根目录放「整个项目共用」的东西，`frontend/` 和 `backend/` 放「只有某一端用」的东西。**

> ⚠️ `.env` 里是明文的后台密码，已经被 `.gitignore` 排除，不会进仓库。要传给别人请给 `.env.example`。

## 二、前端：`frontend/`

### 入口链路

```
frontend/index.html        ← 页面壳，只有 <div id="app">
   └─ /src/main.js         ← 挂载 Vue
        └─ App.vue         ← 根组件（页面切换、登录态、练习主流程都在这里）
             ├─ style.css  ← 全局样式
             └─ 各游戏组件（按需异步加载）
```

> 注意：这个项目**没有用 vue-router**，页面切换是 `App.vue` 里的状态变量控制的。所以「路由」不在单独文件里，而是在 `App.vue`。

### 文件分组（按用途）

| 分组 | 文件 | 作用 |
| --- | --- | --- |
| **入口/外壳** | `main.js`、`App.vue`、`index.html` | 挂载、页面切换、单机练习主流程 |
| **大厅** | `GameLobby.vue` | 联机游戏选择与房间入口 |
| **联机游戏** | `ArenaGame.vue`（赛车+节奏）、`BattleGame.vue`（占领战）、`BossGame.vue`（打 Boss）、`ChaseGame.vue`（追逐）、`RunnerGame.vue`（跑酷）、`CompetitionGame.vue`（比赛） | 每个文件 = 一个玩法 |
| **游戏子部件** | `BattleMap.vue`（Three.js 地图）、`RaceBoard.vue`、`RhythmBoard.vue`、`RunnerLeaderboard.vue`、`StatsBar.vue` | 只被上面某个游戏引用 |
| **练习部件** | `Keyboard.vue`、`BeginnerKeyboard.vue`、`PinyinLineInput.vue`、`BugFeedback.vue` | 虚拟键盘、拼音输入行、反馈弹窗 |
| **数据/逻辑** | `lesson-bank.js`（题库）、`lesson-expansion.js`（题库扩充）、`practice-progress.mjs`（练习进度）、`chase-motion.mjs` / `chase-camera.mjs` / `runner-motion.mjs` / `runner-route.mjs` / `rhythm-timing.mjs`（纯函数计算） | 不含界面，可被测试直接引用 |
| **3D 场景** | `chase-scene.js`、`chase-assets.js`、`runner-scene.js`、`runner-assets.js`、`runner-effects.js`、`rhythm-stage.js` | Three.js 场景搭建 |
| **样式** | `style.css`（全局）、`arena.css`、`battle.css`、`boss.css`、`chase.css`、`race.css`、`runner.css` | 一个玩法一个样式文件 |

**命名规律：前缀就是玩法。** `chase-*` 全属于追逐战，`runner-*` 全属于跑酷，`rhythm-*` 属于节奏。看前缀就知道归属。

## 三、后端：`backend/`

### 入口链路

```
npm start
 └─ vite build            ← 先把 frontend/ 编译进 public/
 └─ node backend/server.js ← 后端入口：读 .env、开数据库、起 HTTP 服务
      ├─ database.js      ← 建表/迁移（better-sqlite3）
      └─ app.js           ← 所有 HTTP 路由（API + 静态页 + 管理后台）
           └─ 各玩法房间模块
```

### 文件分组（按职责）

| 分组 | 文件 | 作用 |
| --- | --- | --- |
| **入口** | `server.js` | 端口、数据库连接、进程事件日志（`data/runlogs/server-events.log`） |
| **路由总集** | `app.js` | 全部接口：注册登录、练习成绩、排行榜、各游戏的 `/api/*`、管理后台、静态资源托管 |
| **基础能力** | `database.js`（建表）、`auth.js`（会话/密码/鉴权）、`scoring.js`（打字计分）、`seed.js`（初始数据） | 被所有玩法共用 |
| **玩法房间** | `arena.js`（赛车+节奏）、`battle.js`（占领战）、`boss.js`（打 Boss）、`chase.js`（追逐）、`runner.js`（跑酷）、`competition.js`（比赛） | 每个文件 = 一个玩法的服务端状态机（座位、计时、结算） |
| **规则计算** | `race-speed.js`（车速与档位）、`rhythm-chart.js`（谱面与判定） | 纯计算，有独立测试 |

> 房间状态存在**内存**里，重启服务会重置进行中的对局（已结算的成绩在 `data/typing.db` 里，不会丢）。

## 四、一次操作走完前后端

```
浏览器（frontend/）
   │  fetch('/api/arena/join', ...)          ← 请求由前端发出
   ▼
Express（backend/app.js）                     ← 路由在这里收
   │  调用房间模块（arena.js / battle.js …）  ← 规则在这里算
   ▼
SQLite（data/typing.db）                      ← 成绩落库
   │  JSON 返回
   ▼
浏览器（frontend/）渲染                        ← 界面在这里更新
```

## 五、我要改 X，该动哪个文件？

| 需求 | 改这里 |
| --- | --- |
| 首页样式、按钮、文案 | `frontend/src/App.vue` + `style.css` |
| 练习题库 | `frontend/src/lesson-bank.js` |
| 某个联机玩法的界面 | `frontend/src/` 下对应的 `XxxGame.vue` + 同名 `.css` |
| 某个玩法的规则（时长、计分、座位） | `backend/` 下对应的 `xxx.js` |
| 新增/修改接口 | `backend/app.js` |
| 排行榜、用户、登录 | `backend/app.js` + `auth.js` + `database.js` |
| 车速/档位手感 | `backend/race-speed.js` |
| 节奏判定宽严 | `backend/rhythm-chart.js` |

## 六、还没整理的（可选）

目前 `frontend/src/`（40 个文件）和 `backend/`（14 个文件）都是**平铺**的，靠命名前缀区分归属。如果要进一步整理，可以按功能建子目录：

```
frontend/src/
  App.vue  main.js  style.css
  views/        GameLobby.vue
  games/        arena/  battle/  boss/  chase/  runner/  competition/
  components/   Keyboard.vue  StatsBar.vue  RaceBoard.vue  ...
  lib/          lesson-bank.js  practice-progress.mjs  *-motion.mjs  ...
  styles/       arena.css  battle.css  ...

backend/
  server.js  app.js
  rooms/        arena.js  battle.js  boss.js  chase.js  runner.js  competition.js
  core/         database.js  auth.js  scoring.js  seed.js
  rules/        race-speed.js  rhythm-chart.js
```

这样做的代价：所有 `import './X.vue'` / `require('./X')` 都要改路径，需要跑一遍 `npm test` 和构建验证。**在改之前先把当前改名（`src/` → `backend/`）提交一次**，出问题才好回退。
